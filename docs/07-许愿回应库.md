# 许愿回应库（2026-11-14）

用户写下愿望后，不再播放每个分类固定的三句引导语，而是从回应库里匹配一条最合适的回应来播。不接大模型，全部是本地规则。

## 规模

| 项目 | 数量 |
|---|---|
| 愿望意图（加薪、考研、减肥、手术顺利、放下前任、脱单、猫咪走丢……） | 131 种，7 个分类各有一个兜底 |
| 每种意图的针对性核心句 | 5 句，共 655 句 |
| 开场句（7 个分类 × 4 种情绪） | 168 句 |
| 行动句（每个分类 12 句） | 84 句 |
| 收尾句（早上、白天、傍晚、夜里各 12 句） | 48 句 |
| **完整回应（开场 + 核心 + 行动 + 收尾）** | **1,048,000 条，没有重复** |
| 录音 | 955 句，每句单独录，播放时四句接着放 |

一条完整回应的例子（愿望「考研上岸」，晚上许的）：

> 你的心愿，已经被稳稳收下。愿初试分数漂亮，复试从容自信。你的坚持，正在悄悄改变结果。晚霞很美，愿你的心愿也一样美好地实现。

## 匹配算法（server/app/wishmatch.py）

1. **规范化**：全角转半角、去标点空格。
2. **关键词打分**：每个意图有一组关键词，命中一个加「字数的 1.5 次方」，越具体分越高；英文单词按两个字算；被同一意图里更长关键词包含的短词不重复算；命中排除词的意图跳过（比如「复合」排除「闺蜜」，「闺蜜和好」就不会被当成复合）。
3. **分类加权**：和用户选的分类一致的意图 ×2；兜底意图 ×0.6，优先具体意图。
4. **说的是谁**：提到猫狗等宠物词时宠物类 ×2，没提到又没选宠物分类时宠物类 ×0.3；提到长辈又在说身体时偏向「父母健康」。
5. **兜底**：关键词一个都没对上时，按相邻两个字的片段和每个意图的关键词、回应句、例句比相似度（罕见的片段分量大）；还不行就用所选分类的通用回应。
6. **情绪**：从用词判断平常、迫切、担心、沉重，选对应语气的开场句；手术、检查默认是担心，去世默认是沉重。
7. **时段**：按手机本地时间选收尾句。
8. **不重复**：同一个人最近 60 次听过的核心句尽量不再出现，连着许五次同一个愿望，五次的核心句都不一样。
9. **危险说法**：提到轻生、自伤时不播回应，显示心理援助热线。

## 准确率

| 测试 | 结果 |
|---|---|
| 各意图自带的 262 条例句（带分类） | 98.5% |
| 同上（不带分类） | 94.3% |
| 115 条另写的口语愿望 | 全对（其中两套 40 条最初是盲测，见下） |

**最诚实的数字是盲测**：第一套没见过的口语愿望只有 55%，补完一轮同义说法后，第二套新的盲测是 80%。也就是说，用户用一种没想到的说法许愿时，大约八成能对上具体意图；没对上时回到同一分类的通用回应，不会答非所问。要继续提高，就是看真实用户的愿望、继续补同义说法（见下）。

## 怎么改、怎么补

- 回应素材：`tools/wishdb/data/*.txt`（格式见同目录 README），同义说法：`tools/wishdb/synonyms.py`。
- 改完重新生成：`python3 tools/wishdb/build.py`（5 秒，输出 server/data/wish_answers.db，约 290 MB，不进代码库）。
- 测准确率：`cd server && .venv/bin/python -m pytest tests/test_wishmatch.py -q`。
- 录新句子：`cd tools/wishdb && ../tts/.venv/bin/python voice.py`（只录还没录的，每句约 2.5 秒）。录好的放在 server/data/wish_voice/，后端看文件在不在决定给不给语音地址，录一句就能用一句。
- 看真实用户的哪些愿望没对上：后端的 wish_heard 表记了每次匹配到的意图；配合 wishes 表里的原文，可以找出落到「xx.general」的愿望，补成新的关键词或新的意图。

## 应用里怎么播

按「许下心愿」的同时去后端匹配、下载四段语音（和仪式开场并行）：

- 仪式里：开场句一出来就念，核心句接在后面。
- 仪式结束：弹出「宇宙的回应」卡片，四句全文，接着念行动句和收尾，正在念的那句亮起来。
- 连不上服务器或超时：回到这个分类原来的三句引导语。
