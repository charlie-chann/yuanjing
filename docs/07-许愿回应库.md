# 许愿回应库（2026-11-15 改版）

用户写下愿望后，从回应库里匹配一条最合适的回应来播。不接大模型，全部是本地规则。

这次改版是因为旧版的回答有时完全不对，原因有三个：

- 意图太少（131 个）；
- 行动句整个分类共用，跟具体愿望经常不搭；
- 关键词没对上时，用字面相似度跨分类兜底，太松。比如「世界和平」配到宠物和睦，「明天不下雨」配到手术顺利，「对我不好的人都受到报应」配到婚姻。

## 规模

| 项目 | 数量 |
|---|---|
| 愿望意图 | **411 个**（财富 60、事业学业 60、外貌 59、健康 57、情绪 58、生活 63、宠物 54） |
| 每个意图的核心句 | 15 句，共 6,173 句 |
| 每个意图的行动句 | 6 句，共 2,471 句（以前按分类共用，现在每个意图有自己的） |
| 开场句（7 个分类 × 4 种情绪） | 168 句 |
| 收尾句（早上、白天、傍晚、夜里各 12 句） | 48 句 |
| **完整回应（开场 + 核心 + 行动 + 收尾）** | **105,216 条，没有重复** |
| 句子总数 | 8,860 句，每句单独录音 |

一条完整回应 = 开场（分类 × 情绪）+ 核心句（意图）+ 行动句（意图）+ 收尾（时段）。
核心句和行动句都属于同一个意图，所以四句话都贴着这个愿望说。每个意图在每种情绪、每个时段下各取 16 条组合，411 × 4 × 4 × 16 = 105,216 条。

每个分类都有三个特殊意图：

- `xx.general`：分类兜底；
- `xx.short`：两三个字的抽象愿望，比如「暴富」「变美」「脱单」；
- `xx.blank`：没写出具体内容，比如「你」「123」「测试」。

另有 `mood.letgo_hurt`：用户希望别人倒霉、消失、遭报应时，不顺着诅咒说，先接住委屈，再把注意力还给用户自己。

所有句子写完后，又按分类逐句审过一遍，共改写约 1,070 句。改的主要是这几类：

- 只适合意图里一部分愿望的句子，比如「世界和平」里的「愿受灾的地方早日重建」；
- 假设了用户身份的句子，比如默认是新娘、默认有孩子、默认病人是自己；
- 承诺过头、给医疗或投资建议的句子；
- 语气消极或说教的句子。

## 匹配规则（server/app/wishmatch.py）

原则：**宁可说得泛，也不能说错。** 按顺序判断：

1. **危险说法**：提到轻生、自伤时，不播回应，显示心理援助热线。
2. **希望别人不好**：
   - 「报应」「诅咒」「出车祸」这类说法，出现就算；
   - 「消失」「倒霉」「过得不好」「被甩」这类说法，要同时提到别人（讨厌的人、前任、那个人……），而且前面没有「不、别、没」才算。
   - 「他的病快点消失」「霉运消失」「报复性熬夜」不算。
   - 算的话，用 `mood.letgo_hurt`。
3. **一个字的愿望**：「瘦」「富」「帅」直接配到对应意图。
4. **关键词打分**：
   - 命中一个加「字数的 1.5 次方」，越具体分越高；
   - 被更长的已命中关键词包含的短词，不重复计分；
   - 命中排除词（`!` 开头）的意图跳过；
   - 所选分类里的意图 ×2；general 打 6 折，short 打 8 折，让具体意图优先；
   - 关键词至少两个字，生成时检查。
5. **说的是谁**：
   - 提到家人（爸妈、老公、孩子……）又没提宠物时，不往宠物意图配。所以在宠物分类里写「妈妈手术顺利」，会配到手术。
   - 提到长辈又在说身体时，偏向「父母健康」。
6. **跨分类要有把握**。最高分的意图不在所选分类时，满足下面任一条才跳过去：
   - 分数 ≥ 4，并且至少是本分类最好的具体意图的 1.5 倍；
   - 本分类没有具体意图对上，而且愿望几乎就是那个说法本身。比如在事业里写「2027暴富」，就配到财富；
   - 别的分类的 general 意图（「心想事成」这类万能话）不跳，用本分类自己的。
7. **没写出具体内容**：一个关键词也没对上，而且有意义的字不到两个，就用 `xx.blank`。
8. **关键词都没对上**：只在所选分类里比字面相似度，门槛高，还要命中至少一个少见的片段。还不够，就用所选分类的 `xx.short` 或 `xx.general`。
9. **情绪**：
   - 从用词判断平常、迫切、担心、沉重，选对应语气的开场句。
   - 只用两个字以上、不容易误判的词：「怕」「哭」「走了」单独出现都不算，「老板走了好运」不会被当成沉重。
   - 手术、哀悼这类意图有默认情绪（写在素材里的 `~` 行），用户写得再急，也用这个语气。
10. **时段**：按手机本地时间选收尾句。
11. **不重复**：同一个人最近 60 次听过的核心句，尽量不再出现。
12. **开场句跟着用户所选的分类走**：许愿页每个分类有自己的意象（金池、山顶、孔明灯……），跨分类配到别的意图时，开场句仍用所选分类的，不出戏。

## 准确率

| 测试 | 旧版 | 新版 |
|---|---|---|
| 盲测 1,088 条（写的人只看过意图名单，含约 15% 刁钻说法）：配对具体意图 | 31.3% | 84.0%（调关键词前）→ 98.9%（调完） |
| 同上：答非所问（既不对，也不是所选分类的通用回应） | 34.5% | 9.7%（调关键词前）→ 0.7%（调完） |
| 独立验收集 433 条（上面调完之后另写）：配对具体意图 | 30.9% | **89.8%**（第一次跑）→ 97.5%（补完） |
| 同上：答非所问 | 38.6% | **6.0%**（第一次跑）→ 0.7%（补完） |
| 真实测出的错例（世界和平、不下雨、报应、消失、王者、火星……） | 全错 | 全对 |

最诚实的数字是独立验收集第一次跑的结果：用户换一种没想到的说法许愿时，大约九成能对上具体意图，答非所问约 6%。「调完」「补完」的数字是照着测试集补关键词之后的结果，会偏乐观。剩下没对上的，基本都落在所选分类的通用回应，或者一个说得通的相近意图上（比如「宠物平安」配到宠物健康）。要继续提高，就看真实用户的愿望、继续补说法。

## 怎么改、怎么补

- 素材：`tools/wishdb/data/*.txt`，格式和写作要求见同目录 README。
  - `- ` 核心句，`> ` 行动句，`? ` 测试愿望，`~ ` 默认情绪。
- 检查一个分类：`python3 tools/wishdb/build.py --check 分类`。
- 生成回应库：`python3 tools/wishdb/build.py`，不到 1 秒。输出 server/data/wish_answers.db，约 30 MB，不进代码库。
- **句子编号是稳定的**：
  - 编号记在 `tools/wishdb/segment_ids.tsv`（要进代码库），同一句话每次生成都拿到同一个编号；
  - 已经录好的音不用重录，删掉的句子编号也不会被新句子占用。
- 测准确率：`cd server && .venv/bin/python -m pytest tests/test_wishmatch.py -q`。盲测集在 `server/tests/wish_cases.tsv`。
- 录新句子：`cd tools/wishdb && ../tts/.venv/bin/python voice.py`。
  - 只录还没录的，每句约 2.5 秒。
  - 后端看录音文件在不在，决定给不给语音地址：录一句就能用一句，没录的只显示文字。
- 看真实用户的哪些愿望没对上：后端的 wish_heard 表记了每次匹配到的意图，配合 wishes 表里的原文，找出落到 `xx.general` / `xx.short` 的愿望，补成关键词或新意图。

## 应用里怎么播

按「许下心愿」的同时，去后端匹配、下载四段语音（和仪式开场并行）：

- 仪式里：开场句一出来就念，核心句接在后面。
- 仪式结束：弹出「宇宙的回应」卡片，显示四句全文，接着念行动句和收尾，正在念的那句亮起来。
- 连不上服务器或超时：回到这个分类原来的三句引导语。
