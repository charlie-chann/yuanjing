## 现在能玩到什么

许愿页左上「进入许愿殿」→ 选山寺或教堂 → 走进去。

| | 山寺 | 教堂 |
|---|---|---|
| 坐的地方 | 山门两侧的回廊，32 个蒲团 | 进门两侧的拱廊，16 张长椅 32 个座位 |
| 院子里 | 许愿树、香炉、三对石灯笼 | 许愿池（喷泉）、柏树、两座烛台 |
| 正面 | 大殿（匾额「愿境」，格扇夜里透光） | 教堂立面（尖拱门、玫瑰花窗、长窗，夜里透光）、钟楼 |
| 能留下的心意 | 挂红布条、挂木牌、上香 | 往许愿池抛硬币、点一支蜡烛 |
| 声音 | 寺里的音乐、风铃、寺钟 | 教堂的音乐、池水声（走近更响）、教堂钟 |

两座殿共有的：

- 走动：点下面的按钮，或者直接点画面上的东西（树、香炉、空蒲团……）走过去；拖动画面环顾四周。镜头是第一人称，走路有脚步的起伏和脚步声。
- 动作：合掌、鞠躬、跪拜（三拜）、静坐（三分钟，带呼吸引导，结束敲一声钟）。
- 许愿：坐着或者留心意时写下愿望 → 合掌低头 → 播回应（回应库里匹配出来的四句，带字幕）。愿望记进「我的心愿」，照常给金币。
- 天色四种（清晨、白天、黄昏、夜晚）和天气四种（晴、雨、雷雨、雪），右上角可以随时换，默认「跟着此刻」：天色看手机时间，天气由服务器定（每 20 分钟一次，所有人看到的一样，冬天才下雪）。
  - 雨：地面淋湿反光、积水里有涟漪、屋檐外沿滴水，屋檐底下是干的、也不下雨。
  - 雷雨：闪电照亮全场，一两秒后雷声，手机震一下。
  - 雪：只积在朝上的、露天的面上。
  - 夜里和阴雨天灯会亮起来。
- 其他人：别人坐在哪、鞠躬跪拜都看得到。真人不多时由内置香客撑场面（36 位，按时段来去，同一时刻所有人看到的一样）。进岛、换了地方（走到树下、进殿……）时，上方的地名下面写着「此刻寺里有几个人」，三秒后连同地名一起淡掉（做动作、特写时不出来）；点右上角的天色瓦牌也看得到。
- 别人挂的红布条、点的蜡烛会出现在树上、烛台上；写在上面的话只有自己看得到。

**没有神像、十字架、圣像**，只有建筑和氛围。原因见 06 第一节（国内宗教信息的许可）；上架前仍然要请律师看一眼。

## 结构

```
unity/Sanctuary/                      Unity 6.3 工程（URP）
  Assets/Editor/Build*.cs             用代码生成两座殿（建筑、材质、灯光、粒子都是代码摆的）
  Assets/Scripts/World/               运行时：GameDirector 总控、CameraRig 镜头、TimeWeather 天色天气、
                                      Pilgrims 香客、Offerings 心意、WorldAudio 声音
  Assets/Shaders/                     表面（淋湿、积水、积雪）、天空、雨雪、粒子
  Assets/Textures, Sky                Poly Haven 的免费素材（CC0）
unity/shots.sh                        不开模拟器，直接渲染几张预览图（改完看效果，十几秒）
unity/export.sh [-simulator]          生成两座殿并导出到 ios/unityLibrary
lib/features/sanctuary/               Flutter 这边：选殿、叠在画面上的界面、和服务器同步
server/app/routers/sanctuary.py       谁在场、天气、心意
```

Flutter 和 Unity 之间只传 JSON 字符串，指令清单在 `GameDirector.cs` 开头的注释里。手势（拖动、点）在 Flutter 这层接，再转给 Unity。

## 常用操作

改了场景或脚本：

```bash
unity/shots.sh 名字 "_a|相机位置|看向哪|时段|天气|视角" build     # 先看预览图，SCENE=Chapel 看教堂
unity/export.sh -simulator                                      # 导出（模拟器版；真机去掉 -simulator）
flutter build ios --simulator --debug                           # 再编译应用
```

换匾额上的字：`python3 tools/unity/gen_plaque.py 两个字`，再导出。

Unity 升级后要重新生成表面着色器：`python3 tools/unity/gen_shader.py`。


## 第三人称和小人（2026-11-14 晚）

**人物**：Quaternius 的免费底模（Universal Base Characters，CC0）加免费动作库（Universal Animation Library，CC0）。
用代码改成 Q 版：头放大约 1.9 倍、整体缩到 0.6；身上的长袍、腰带、鞋是按身体轮廓一圈圈包出来的（`Editor/BuildFolk.cs` 的 `RobeMesh`），跟着骨骼动。
八套样子（僧袍、居士服，几种颜色和发型），第一套是自己，在 `FolkLooks` 里改。

**动作**：站、走（两种速度）、坐椅子来自动作库；合掌、鞠躬、跪下、跪拜、盘坐是在动画上直接改关节（`Scripts/World/Folk.cs`）。关节值是一组组侧面出图试出来的。

**操作**：左下角摇杆走；拖画面转视角；点地面、点树、点空蒲团会走过去；底下按钮照旧。镜头在人身后，被墙和柱子挡住会自己收近。

**其他人**：同一批小人。新来的从山门走进来找位置坐下，走的人起身走出山门；院子里另有几位散步，走到树下、香炉前拜一拜。头顶显示名字。

**花草**：Poly Haven 的草丛、灌木、蕨、野花（CC0），原件是 glTF，用 `tools/unity/gltf_to_obj.py` 转成 OBJ，颜色图和透明度合成一张。寺庙加了三棵红枫。

**踩过的坑**（再改时注意）：
- 动画片段必须是独立的 `.anim` 文件，而且要用「新建再抄曲线」的方式生成；直接引用模型文件里的片段、或用 `Instantiate` 复制，打包到手机上都会丢，人会摆成 T 字或陷进地里。编辑器里看不出来。
- 小人不用动画状态机，用播放图（Playables）按速度混合，见 `Folk.BuildGraph`。
- 关掉了「裁剪引擎代码」，`Assets/link.xml` 保留动画模块。
- 查手机上的 Unity 日志：`xcrun simctl launch --console-pty <设备> app.yuanjing.yuanjing > 文件`，系统日志里看不到。
- 编辑器里的运行模式测试：`Assets/Tests/FolkPlayTest.cs`。
- 走动时贴图闪：贴图必须是三线性过滤（`TextureRules`），带透明的花草树叶要「保住覆盖面积」；运行时强制打开各向异性过滤（`Bridge.Awake`）。
  不要在运行时切换画质档：每档自带的抗锯齿倍数会和渲染设置冲突。
- 走动时「画面忽远忽近」：原来是镜头被柱子、灯笼挡住就猛收近、再慢慢退回。现在只有墙、屋顶、台基挡镜头（`BuildRuntime.CameraBlockers`），
  其余碰撞体放在第 9 层，人会撞上、镜头穿过。加了新的大块建筑要把名字加进这个名单。检查：运行模式测试 `Assets/Tests/CameraWalkTest.cs`。
- 抗锯齿用的是**时间抗锯齿**（镜头上设，`BuildEnvironment`），不用多重采样（两者不能同开）。走动时屋瓦、石条的细线和阴影边缘就不会跳。
  它要靠「运动矢量」才不拖影，所以表面着色器保留了 MotionVectors 这一遍。
- 树叶、草、布条的随风摆动写在 `Shaders/YJSway.hlsl`，**画颜色、算阴影、算深度三遍都要用它**（`tools/unity/gen_shader.py` 生成）。
  只在画颜色那一遍摆的话，叶子和自己的影子对不上，影子会抖、忽有忽无。量闪烁：`unity/alias.sh`（连拍对比）、`unity/alias2.sh`（和 4 倍超采样对比）。

**还不够好的**：
- 免费底模是写实比例改的 Q 版，脸还是成年人的脸，达不到参考图那种圆润可爱的程度。
- 长袍是包出来的，坐下、跪下时腿部会有穿插。
- 合掌、跪拜是改关节摆出来的，没有动作捕捉那么自然。
- 只在模拟器上看过，真机的帧率（人多、花草多）没测。


## 画面闪烁的排查记录（2026-11-15）

现象：站着不动，地面、建筑、窗格每隔几秒到几十秒整片变一次样子（灯光忽有忽无、窗格和灯笼纸一会儿发光一会儿不发光）。
编辑器里出图完全看不出来，只有手机（模拟器）上有。

**怎么量**（以后再出现闪烁照这个来，别靠肉眼和猜）：
- `SIMCTL_CHILD_YJ_PROBE=5 xcrun simctl launch --console-pty <设备> app.yuanjing.yuanjing > 日志`：进殿后 `Scripts/World/RenderProbe.cs` 会逐项关功能，每项 60 秒，量地面和窗格颜色的跳变次数写进日志。
  `YJ_PROBE=1` 量相邻两帧的差（静止画面应该接近 0）。
- 录屏逐帧分析：`xcrun simctl io <设备> recordVideo`，再拆帧比较。两种状态的清晰画面并排看，比任何推理都管用。

**根本原因**：`tools/unity/gen_shader.py` 里删除「延迟渲染那一遍绘制」的代码写错了，只删掉了那一遍的名字和光照模式标签，内容还留着。
渲染管线对没有标签的绘制照画不误，于是每个物体每帧被画两遍：一遍正常的，一遍只输出底色加自发光、不算灯笼的灯光。
两遍画在同一个位置，谁盖住谁取决于绘制顺序；画面里有人在动，顺序就会变，于是地面、建筑、窗格在「有灯光没发光」和「有发光没灯光」之间来回跳。
把人隐藏以后顺序不变，所以不跳。编辑器出图时顺序碰巧稳定，所以一直没发现。

修复：脚本改成从单独成行的 `Pass` 删起，并加了自检（每一遍都必须有名字和光照模式标签，否则生成时直接报错）。
验证（模拟器，夜晚下雨，站着不动）：修之前 70 秒里整幅画面突变 16 次，修之后山寺 120 秒、教堂 75 秒都是 0 次。

**顺带改掉的几处**（各自都是真问题，但不是主因）：
1. 时间抗锯齿在模拟器上让静止画面每帧都在抖（相邻帧差 0.54，SMAA 是 0.03）。改回 SMAA。
2. 环境光遮蔽默认的噪声每帧换一张，暗角里有细碎的闪。改成固定图案。
3. 反射探针的混合和盒投影在没有探针的场景里关掉。
4. 灯和窗格的发光颜色直接设到材质上，不用每个物体单独的属性块。
5. 遮挡高度图设到每个材质上，不用全局贴图。
6. 人坐下、跪下时「身体下沉多少」的算法原来依赖上一帧的结果，模型被隐藏时会越滚越大变成无效数。已改成不依赖上一帧。
7. 进殿时已经在场的香客直接坐在位子上，不再一起从山门挤进来。

**试过但没用、已经撤回的**：显卡蒙皮改处理器蒙皮、Forward+ 渲染路径、关图形多线程作业、关渲染管线的着色器版本裁剪
（最后这个还会让我们的着色器变成四百多万个版本，打包要几个小时，千万别开）。

**走过的弯路**：前三轮都是在编辑器里出单张图、凭推理改设置就说修好了，其实一次都没在手机上量过。
后来逐项关功能做对照，发现只有「把人隐藏」才不闪；再把两种状态的清晰画面并排一看，一个缺灯光、一个缺发光，
才想到是同一个物体被两种方式各画了一遍，回头查着色器文件，一眼就看到那遍没有名字的绘制。导出日志里其实一直写着 `Pass ""`。

## 第三座：湖心小寺（俯视卡通画风，2026-11-15）

用户看了一款俯视卡通风的小游戏，要求在许愿页再加一个入口、做成那种画风，并且更精致。玩法不变（同山寺：走动、入座、合掌鞠躬跪拜静坐、挂红布条、挂木牌、上香），多人照常。原来两座殿没动。

入口：许愿页左上多了「湖心小寺」，直接进；「进入许愿殿」的选殿面板里也多了一张卡片。

### 是什么样

一座湖心小岛。坐船到码头 → 沙滩 → 牌坊 → 石板路 → 香炉和圆形铺地 → 大殿前的露天石台 → 重檐大殿。（这是 11-15 的样子；岛、大殿、座位现在的样子见文末「大殿扩建（2026-11-19）」：岛往北长了一块，大殿是面阔九间的大殿，石台上是六条石凳，20 个垫子在殿里。）西边是许愿树（四周一圈木桩拉着绳子，布条和木牌挂在绳上）、红枫、银杏、石碑；东边是荷花池（有锦鲤）、花树、钟亭；后面是松和竹。水是通透的，岸边有浪花，水底有流动的光纹。

镜头在高处斜着往下看，朝向固定（屏幕上方永远是北）。**能走到的地方都不在屋顶下**（后来改了：能进殿，操作是「摇杆走路 + 拖屏自由环绕 + 捏合远近」，见文末）；走到牌坊、树冠后面时，挡住人的那一块会用网点镂空。坐下、做动作、留心意时镜头拉近。

### 和另外两座殿不一样的地方

| | 山寺、教堂 | 湖心小寺 |
|---|---|---|
| 模型 | Unity 里用代码拼（`Build*.cs`），贴实拍材质 | **Blender 里用脚本建**（`tools/blender/`），颜色画在顶点色上，不用贴图 |
| 着色器 | `Yuanjing/Surface`（照着 URP Lit 改的，写实） | `Yuanjing/Toon`（手写：亮面暗面两段、暗面偏蓝紫）和 `Yuanjing/ToonWater` |
| 镜头 | `ThirdPersonCamera` 贴在身后 | `TopDownCamera` 俯视 |
| 小人 | `Folk_*.prefab` | `Folk_toon_*.prefab`：同一副骨架和动作，换卡通材质，有两位戴斗笠 |
| 后期 | `Post.asset`（电影式色调映射） | `PostToon.asset`（中性色调映射，不把鲜艳的颜色压灰） |

总控、香客、心意、天色天气、声音、Flutter 页面、后端全部共用。两种镜头都继承 `PlayerCamera`，总控只认它。

### Blender 建模管线

装的是 Blender 4.5 LTS（`/Applications/Blender.app`，官网下载、核对过校验值）。全程无界面跑脚本：

```bash
tools/blender/build_all.sh                 # 全部重做（约 60 个模型，十几秒）
tools/blender/build_all.sh hall lantern    # 只重做某几个
```

- `kit.py`：公共函数。倒角方块、圆柱、旋转体、一团（树冠）、石头（凸包再倒角）、管子、**中式屋顶**（四面坡、檐角上翘、瓦垄起伏，重檐用 `inner`）、把缝隙和墙脚算暗一点乘进顶点色、导出、出预览图。
- `palette.py`：统一配色。所有模型只从这里取色。
- `layout.py`：平面布局（码头、路、香炉、树、池塘、石台、大殿在哪）和地形高度。**Unity 的 `BuildIslet.cs` 开头有一份同样的数字，改一边要改另一边。**
- `terrain.py`（地面、铺地）、`buildings.py`（大殿、牌坊、钟亭、码头、小船）、`plants.py`、`props.py`。
- 每个模型出一张预览图在 `tools/blender/preview/`，先看这里再进 Unity。
- 导出的是自己定的格式 `.yjm`（没走 FBX：坐标轴、缩放、顶点色的色彩空间都容易错），Unity 那边 `Editor/YjmImporter.cs` 读。一个模型按材质分成几个部件：`toon` 普通、`leaf` 双面的叶片、`glow` 夜里会亮的。
- 顶点色的第四个数是「随风摆动的幅度」；uv.x 是每一团叶子的相位，uv.y 是自发光。
- 地形另外导出一份 `Assets/Toon/islet_map.bytes`（高度、离岸多远、离池塘多远），Unity 撒草和围边界时用。

Blender 里的坐标：X 向右、Y 往里、Z 向上；导出时换成 Unity 的 (x, z, y)。

### 着色器要点

- `YJToon.shader` 四遍绘制（ForwardLit、ShadowCaster、DepthOnly、DepthNormals）**每一遍都写了 Name 和 LightMode**。少写一个就是上次闪烁的根因。
- 光照配比在材质上：`_Ambient` 0.5、`_SunScale` 0.2，亮面大约等于模型上的颜色本身。时段预设是这座殿自己的（`IsletLighting`）：清晨黄昏的太阳抬到 26°–30°，不然俯视下整片地都在影子里；夜里的环境光调亮到看得清。
- `_Legacy = 1` 是「普通模型」模式：小人、布条、香这些不是 Blender 脚本做的，颜色来自材质和贴图，摆动幅度在顶点色的红色通道。
- 视线镂空：`TopDownCamera` 每帧把人的位置写进全局的 `_YJSee`，着色器把「镜头到人」这条线附近、比人头高的东西用 4×4 固定网点裁掉。网点图案固定，不闪。第三人称的两座殿里 `_YJSee` 是 0，不生效。
- 云影：`_YJCloud`，亮面上缓缓飘过的大块明暗，只在俯视镜头下开。
- 水面要读镜头的深度图（算水深、岸边浪花）。URP 设置里已打开（之前那个开关的名字写错了没生效，是靠环境光遮蔽顺带生成的）。

  - 石台 14 厘米太高，走上去脚尖插进台阶 → 降到 7 厘米；上台阶时高度立刻跟上。
  - 裙子：加大腿碰撞球和一点重力（`SpringBones.colliders`）；女生坐下、跪下露出白色内衣 → 转换时把裆部的白色像素染成深藏青安全裤（`vrm_import.py` 的 `safety_shorts`）。
  - 进殿不再自动走，站着不动。
  - 镜头：走动时慢慢转到行进方向（俯视每秒 15 度、平视 40 度），往前多看一点；转身往回走时不转（免得画面翻过来）。
- **还没修好的**：走路时着地的脚还有些滑（约 0.1–0.15 米/秒）；踏上铺地石板边时脚尖会插进去 5 厘米左右一瞬间；进殿后人在栈桥上（编辑器里测是在院子里，模拟器里在栈桥上，原因没查清）；模拟器里用工具拖不动摇杆，走路只在 Unity 测试里验证过。

## 大殿扩建（2026-11-19）

用户的要求：进大殿的面积放大 10 倍；要有宏伟的佛像、观音；门口一直开着；支持俯视；大殿放 20 个垫子；门口不放垫子、放石凳休息、不要太多；靠近坐垫才显示跪拜；细节做好。

**操作**（这一轮先做的）：摇杆走路 + 拖屏自由环绕（能一直压到俯视）+ 捏合拉远拉近。`ThirdPersonCamera.free / zoomScale / Subject`，`ViewSwitcher` 默认 `level`、`SetReach`；进殿不再锁平视、不换视角（`view` 消息里 `locked` 一直是 false，多了 `inhall`）。新指令 `reach {x}`、`fish {action, kind}`、`ring`；`near` 多了 `bird`、`bell`、`water`（sea / pond / 空）。新组件 `Fishing.cs`、`BellRing.cs`。

**岛和大殿**（Blender 那边的交接见 `tools/blender/out_v2/HALL_V2.md`，数字以它为准）：
- 岛往北长了一块圆角方形的地（中心 (0, 29)，x ±33.2、z 4.4…53.6），成了「北大南小」的葫芦形；地形、`islet_map.bytes`、地面贴图的范围是 x -37…37、z -29…59。码头、主路、牌坊、香炉、许愿树、池塘、石台、钟亭都没动。
- 大殿：面阔九间的重檐庑殿，模型原点 `HallAt = (0, 0, 27.1)`，台基 x ±23.1、z 10.8…43.4（高 1.08），**殿里 x ±20.44、z 16.64…40.74（40.9 × 24.1 米，985 平米，是老殿的十倍）**，金砖地面高 1.07，净高 12.5（天花梁底 12.75）。55.7 万个三角形。
- 正面中间三间是门，门扇叠在门洞两边，**一直开着**；门槛只有 3 厘米，不做碰撞，直接走过去。台阶在正面（x ±8.2，7 级，z 9.18…10.80）。
- 地面贴图 8192 × 8192（密度 0.9 × 1.07 厘米一个像素，比以前的 4096 还密）：iOS 上按 8192、ASTC 8×8 导入（设置在 `BuildCore.cs` 的 `OnPreprocessTexture` 里，单给 `islet_ground` 开的例外），包里约 22 MB（以前 4096、ASTC 5×5 约 14 MB；8192 用 5×5 要 57 MB，用不起；照旧限到 4096 的话一个像素 2 厘米，比扩建前还糊）。

**殿里**（`Editor/BuildHall.cs`；坐标是世界 (x, z)）：
- 佛坛：`altar_dais` 模型放大（左右、高低 1.72 倍，前后 2.2 倍）成 20 × 4.33 米、高 1.47（坛面 2.535），中心 (0, 33.715)，背靠扇面墙。
- 三世佛：中心 (0, 33.75)、(±7, 33.75)，正对三间门；**放大 2.3 倍**——释迦像高 6.7 米、肉髻顶 9.2 米，连背光顶到 11.2 米；左右两尊肉髻顶 8.2 米、背光 9.9 米。贴金、Mesh LOD 的做法没变。
- 观音：`guanyin`（立像）在西侧胁侍位 (-18.6, 28.8)，面朝东，放大 2.6 倍（像高 6.8 米，背光 `mandorla_guanyin` 顶到 10.1 米），座子是 `altar_dais` 缩成的一小段须弥座（高 0.94），像前一张小供桌。东侧没有像（文殊、普贤的模型没有做）：摆一张贴墙的供桌（香炉、花觚、烛台、长明灯），壁画露着；以后有 `wenshu` / `puxian` 模型放进 `Toon/Models` 重新生成场景就会摆上（代码里判空）。
- 陈设（都是人的尺度）：坛前五张供桌（中间大的在 (0, 30.6)，左右两尊前 (±7, 30.65) 各一张带香炉，之间 (±3.5, 30.65) 各一张花果桌）、坛面前沿九盏长明灯、中间供桌两旁落地大烛台、佛坛两头落地大花觚；宫灯 11 盏（放大一倍，垂到 9 米上下）、幡 6 条（放大 2.2 倍）；磬 (11.6, 30.4)、木鱼 (12.5, 30.4)、经桌 (-12, 30.4)、功德箱 (3.5, 19.4)。
- **20 个垫子**：拜垫 5 块在 z 29.2——x -1.5、0、1.5（释迦像前）、±7（左右两尊前），序号 0–4；静坐的蒲团 15 个，都朝北——z 26.4 和 24.8 两排各 6 个（x ±2.4、±3.9、±5.4），z 23.2 一排 3 个（x 0、±3.9）。离门（墙内皮 z 16.64）6.5 米以上，门口那五米前槽不放垫子。走到垫子跟前才显示「坐下」「跪拜」（`sitRadius` 1.2、`matRadius` 0.9，没变）。上香站 (0, 29.92)，香插在 (0, 2.032, 30.4)。
- 灯：殿里 8 盏点光（中厅、佛前三盏、两侧廊、后廊、门里；金砖地是一整块，最多吃 8 盏）；殿外檐下两盏挪到 (±8.7, 4.3, 12.3)、范围 4 米，够不着殿里。
- 碰撞：台基、台面、七级台阶和斜坡（`StairRamp`）、垂带、栏杆、墙、槛窗、门柱、叠着的门扇、天花、前廊十根柱子、殿里十六根金柱、壁柱、扇面墙、佛坛、佛像和观音（只挡镜头）、供桌陈设。占地的东西（`HallSolids`）一份数据同时用来摆碰撞盒和登记成寻路要绕开的。
- 寻路：`GameDirector.hallRect` 是整座殿，`hallWalkMaxZ` 放到后墙（扇面墙后面的后廊能绕佛一圈）；网格还是 0.1 米一格（404 × 238 格），「两点之间能不能直着走」改成查算好的网格（`HallFreeFast`），不然殿大了每次找路要量几十万次障碍。进出殿三间门挑顺路的（`hallSideDoorsOut / In`）。
- `InteriorCull`：门洞是三间门连成的一个长方（x ±10.04，高 1.10…5.95）；下檐伸到 z 10.1、高 8.25，镜头抬到「门槛 → 檐口」那条线以上（坡度 1.15）殿里才不画，在那以下按门洞的四棱锥挑——站在院子里透过三间门看得到三尊大佛。
- 镜头：`hallCeiling` 12.75，殿里自由环绕能压到俯视、拉远到十米，看得到 20 个垫子的布局；殿外抬高镜头时屋檐、树冠照旧镂空。

**殿外**（`Editor/BuildIslet.cs`）：
- 石台上的 60 个蒲团去掉了，换成 **6 条石凳**（`stone_bench`，缩到 0.9：长 1.35、高 0.43），左右各三条：中心 (±6.0, 3.6 / 5.6 / 7.6)，面朝大殿，中间留十米宽的过道；每条坐两个人，一共 12 个座位（序号：凳 × 2 + 西 0 / 东 1）。
- 坐石凳用 `benchSeats` 那一套，加了 `benchStep`（0.46）：座位点在凳面下 2 厘米（x ±0.31；`seatDrop` 0.4075，量过：这个高度坐着脚正好踩在石台上），人走到凳前、背对凳子站好，原点滑上凳面坐下（`Folk.SitBench`，0.6 秒），起身滑回凳前（0.9 秒；滑的时候不跟地面、不开碰撞胶囊，每帧姿势摆好以后量脚尖，低了当场把人托住，脚不插进地里；老办法摆的坐姿收完那一帧髋会弹十几厘米，记下来慢慢放掉）；石凳有碰撞（只挡人），坐下、起身的人那时没有碰撞胶囊，不会被顶开。玩家走到凳前 `near.seat ≥ 0`，内置香客也会来坐。原来「一排排蒲团 + 走道」的那套路线玩家这边不用了（`laneOffset` 是零，石凳登记成要绕开的东西）；香客那边还按「中间过道 → 凳前 0.75 米那一条 → 凳前」走。
- 北边新地块：殿两侧台基外是五米宽的草地甬道，外沿各一排树（松、枫、银杏、杂树、花树）、竹丛、三盏石灯笼；殿后一排松、正中一大丛竹、三盏石灯笼，两个角的土丘上各一棵老松；岸边一圈石头、芦苇、荷花；草、花、蕨、灌木铺到整块地（草 21 万根，以前 7.8 万）。贴着台基能绕殿走一圈，台基上（墙和栏杆之间）也能绕一圈，都接进了自动走路的路网。团子、墨墨、豆包、汤圆的家挪到了台基外。
- 岸边看不见的矮墙改成按 `islet_map` 的等值线一段段摆（岛不再是绕一个中心的一圈）。
- 钟亭：挂上了单独做的 `temple_bell` 和 `bell_striker`（钟亭模型里自带的那口简单的钟、撞木在生成场景时从网格里去掉了，Blender 脚本没改）。敲钟时人先走到撞木尾巴旁边，撞木绕吊点往后荡 26 度、撞过去 13.5 度正好碰到钟（`BellRing.swingAxis / pullBack / strike`）。
- 钓鱼：竿梢 `Fishing.rodTip` 按 `fishing_rod` 模型改成 (0, -0.075, 2.6)。
- 小动物：`pets` 指令的每一项可以多带第五段礼物编号（`teddy:2:1:1:pinecone`），叼的模型换成 `gift_<编号>`（`dried_fish` 用 `gift_fish`，没有这个模型就还叼原来那件）；喂的是鱼（`petact` 的 `item` 是鱼的编号）就在它嘴边放那条鱼（`fish_<编号>`）代替食盆。鱼、礼物模型上发光的部件（月光鱼、珍珠）白天也亮（`toon_shine`），鳍和叶子不积雪（`toon_leaf_dry`）。

**还没做好的、要知道的**：
- **服务器的人数上限跟着座位数走**（`sanctuary.py` 的 `cap = len(taken) + seats * 2 // 3`）：石台上现在只有 12 个座位，联网时内置香客最多 8 位（以前 60 个蒲团是 40 位），岛上会冷清，殿里也基本没人进（不到 8 位香客不请人进殿）。没联网的本机人流不受影响。要在服务器把上限和座位数脱开（这一轮不能动 `server/`）。
- 东侧胁侍位没有像（文殊、普贤的模型没做），先摆了一张供桌。
- 钟亭自带的钟是在 Unity 里从网格上去掉的（`BuildIslet.HangBell`），`buildings.py` 的 `pavilion` 没改；以后重出钟亭模型时最好在 Blender 那边去掉。
- 佛坛是把老的 `altar_dais` 模型拉大的（前后比左右多拉了近三成），坛侧面和俯视时莲瓣、壸门的比例是变了形的；金砖地那张手绘的地面图（`floor_jinzhuan.png`）是按老殿 13 × 7.6 米画的，现在拉到 41 × 24 米，砖缝以外的磨痕、走道放大了三倍。要好看得各重出一版。
- 石凳上坐着的姿势是老的「椅子坐姿」（程序摆的关节，不是关键帧动作），坐下、起身是原点滑过去加姿势淡入，没有专门的动作段。
- 北边新地块上草有 21 万根（全岛以前 7.8 万），真机上没测；嫌重先把 `GrassField` 的密度降下来。
- 台阶只有正面一处；两侧和殿后的甬道是草地，没有铺路。
- 敲钟时人站在撞木尾巴旁边做「往前推」的手势，手没有真的握在撞木上。
- 只在编辑器里验证（测试和截图），没有导出到 iOS、没有在模拟器和真机上跑。
